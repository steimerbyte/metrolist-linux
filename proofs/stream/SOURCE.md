## Model deviations

- `expiry(now: SystemTime, ..)`: `SystemTime` is a platform type, not a Verus
  value. On the pinned Linux target it is a `timespec` (`i64` seconds + nanos),
  and `SystemTime::checked_add` fails when the sum leaves that `i64` range. The
  model works on **epoch seconds as `u64`**:
  - domain: `0 ..= i64::MAX` epoch seconds corresponds exactly to representable
    platform instants; the model does **not** model pre-epoch times or the
    nanosecond representation (`Duration::from_secs` is not modelled);
  - the proven overflow rule (`now + delta > u64::MAX` -> `None`) is
    conservative with respect to the platform: the platform reports `None`
    from `i64::MAX` upward, the model from `u64::MAX` upward, so between the
    two the model may return `Some` where the platform returns `None`. The
    margin decision (`expires_in <= margin` -> `None`) is exact on the whole
    domain.
- `parse_content_range`: `str::split_once`/`trim`/`parse` are outside the
  subset; the model proves the **post-parse validation** exactly as the real
  function performs it (`START > END` and `END >= TOTAL` rejected, `*` total
  kept as `None`). Malformed-input rejection is delegated to the parser.
- `pick_itag`: `[251, 140].into_iter().find(..)` is unrolled into two scans
  over `formats` (same preference, same short-circuit) because iterator
  adapters are outside the subset. The `playable` filter is kept verbatim in
  effect: `!auto_dubbed` **and** a non-empty direct URL. `AudioFormat.url` is
  modelled by `url_len: Option<u32>` (`Some(0)` is the empty string),
  `mime`/`bitrate` are dropped.
- `pick_itag`'s predicate uses `url_len.is_some() && url_len.unwrap() > 0`
  rather than `matches!(url_len, Some(n) if n > 0)`: Verus
  `0.2026.11.02.8bf68ee` panics on `matches!` with a guard
  (`vir/src/ast_to_sst.rs:3873`). Same value, same short-circuit.
- `base64url_nopad`: the real function pushes `char`s into a `String`;
  `String` is outside the subset, so the model builds `Vec<u8>`. The real
  64-byte `ALPHABET` table is kept (not re-encoded arithmetically); only
  `chunks(3)` becomes an index loop with the same `remaining > 1/2` checks and
  `get(1)/get(2)` defaults, and `push(char)` becomes `push(u8)`. Proven:
  output length `ceil(4n/3)` (`encoded_len`) and every byte comes from the
  table. **Injectivity is CANDIDATE** (decode/round-trip lemma), see
  `docs/PROOFS.md`.
- `chunk_ranges`: verbatim; the proof additionally pins that every non-last
  range is exactly `chunk` bytes (the source's `min(total-1)` only shortens
  the last one).
- `parse_visitor_data`, `cookie_value`: `str::find` and slicing are outside the
  subset; not modelled (documented as OUT-OF-SUBSET).
- `content_total`, `parse_content_range_total`, `StreamCache`/`cached`/`store`:
  `reqwest`/`HashMap`/`Mutex` and `str` scanning; not modelled.

- `sapisidhash` (`context.rs`, and its twin in `cookies.rs`): the v0.1.2
  account fix changed the hashed field order to `ts sapisid origin` — the
  order the server recomputes; the old `ts origin sapisid` answers signed-out.
  **OUT-OF-SUBSET, test-pinned, not proven**: `SHA-1` (external crate) plus
  `format!`/`String` hex building are outside the Verus subset, and proving
  the order from a hash is not meaningful. The fix is pinned by the vector
  tests (`sapisidhash_matches_the_documented_vector` in `context.rs`,
  `sapisidhash_matches_the_known_vector` in `cookies.rs`, both checked against
  `sha1sum`), and `context.rs` is a declared source only for drift.
